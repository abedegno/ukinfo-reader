# UK-Info v14 support implementation plan

**Goal:** Read the supplied March 2008 v14 source through the existing search/export API, including available businesses, with complete validation and documented anomalies.

**Architecture:** Use an exact source profile and explicit decoder dispatch. Reuse earlier c-tree, record and address code only after source-wide and original-decoder comparisons establish compatibility. Preserve source precision and uncertain values. Keep the existing five editions working.

**Constraints:** No source data, original binaries, recovered disassemblies or personal records in Git. Invent all fixtures. Retain at least 5 GiB free. Do not import into the public NAS as part of local decoder implementation. Do not execute installers. Preserve existing documentation edits.

## Tasks

- [x] Extract and fingerprint the installer dictionaries and data disc without copying whole raw images. Recover the decoder locally and identify record constructors, length functions and address formatting routines.
- [x] Establish differences using complete physical scans and invented-input comparisons against original routines. Record metadata-only evidence and unresolved source anomalies.
- [x] Add failing invented-fixture tests for the verified differences, malformed inputs and distinct edition dispatch. Implement the minimum explicit v14 reader without broadening existing edition assumptions.
- [x] Verify joined residential/business fields and all reference bounds. Validate full source coverage, source identities and available indexes. Register support only after this gate passes.
- [x] Integrate folder/media import where validated; document exact source layout and any unsupported media paths. Run existing edition regression tests, source validation and CLI smoke checks with private output.
- [x] Update README, editions, format guide, changelog and metadata-only validation reports. Review the diff and public-tree checks before committing.

## Review focus

- Name masks and optional field widths can differ despite familiar filenames.
- Business classification indexes can use custom comparison rules; bytewise order is not assumed.
- Partial postcodes and missing names must remain explicit, never invented.
- Two-disc media must not mix dictionaries from different releases.
- Counts describe source occurrences rather than unique people or households.

## Implementation decisions

- Ruling: prepare the exact MDF/IMG pair with a dedicated command, then use the
  existing desktop folder importer. This avoids an unrequested two-disc wizard
  redesign while keeping source identities checked end to end.
- Ruling: extract factual telephone-prefix metadata from the user's verified DLL
  instead of shipping that dictionary or any original code.
- Review found stale original county/name overrides. v14 follows stored parent
  references and flags 50 intentional differences; all 27,957 locality rows were
  compared with the original formatter, with zero unexplained differences.
- Source counts: 43,799,502 entries, including 6,092,008 businesses. The public NAS
  stays on its existing five editions until a separate import/acceptance task.

Validation: 81 Python tests passed (two optional checks skipped); full v14 source scan, all 2003–2005 source rescans, exact two-disc preparation, original physical/telephone/locality comparisons and package contents checked. The reviewed locality correction has an invented regression fixture. Source controls remain raw metadata with unverified broader semantics.
